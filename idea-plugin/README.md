# 注释译读 · IntelliJ IDEA 验证版

分支导航：[IntelliJ IDEA · master-idea](https://github.com/puhui999/ai-comment-translator/tree/master-idea) · [VS Code · master-vscode](https://github.com/puhui999/ai-comment-translator/tree/master-vscode)。本文对应 IDEA 插件 ZIP；VS Code 使用其分支中的 VSIX 安装包。

版本 `0.1.6`。默认在原注释位置显示 AI 译文，悬停查看原文，点击后查看、编辑原注释，光标和选区离开后自动恢复译文。独立注释采用无边框多行排版；设置中也可选择原文与译文上下对照。显示使用编辑器的折叠或 Inlay 机制，译文不写入源文件，保存、撤销、普通复制和 Git diff 仍基于源码。

开发基线为 IntelliJ IDEA `2026.2.0.1 / 262.8665.337`，安装包声明的兼容范围为 `262.8665` 至 `262.*`。当前是 IDEA 预览版，尚未承诺其他 JetBrains IDE 或旧版 IDEA 的兼容性。

## 0.1.6 文档注释修复

- 修复合法中文 JavaDoc 被结构校验误拒：允许同一说明段内的 `{@link}` / `{@code}` 随中文语序调整位置，仍保留标签、引用目标、代码和重复次数；不同参数说明或 HTML 段落之间不能搬移引用。
- `@return` 后的 `{@link Builder}` 等行内标签不再被误当成 `{Type}` 类型声明。真正的 JSDoc/PHPDoc 类型与参数名仍校验保护。
- 错误提示区分模型输出截断、文档结构不匹配，以及空译文/缺失或重复 ID。没有模型的原始响应时，不能仅凭旧提示断定发生过截断。
- 当前 IDEA 请求不主动发送 `max_tokens` / `max_completion_tokens`；单条字符上限限制输入，不会截断发送的注释。失败结果不缓存，安装修复版后重试当前文件即可复用成功缓存并补翻失败项。

## 安装与离线体验

1. 从 [0.1.6 Release](https://github.com/puhui999/ai-comment-translator/releases/tag/idea-v0.1.6) 下载 [idea-comment-translator-0.1.6.zip](https://github.com/puhui999/ai-comment-translator/releases/download/idea-v0.1.6/idea-comment-translator-0.1.6.zip)。可用同一 Release 附带的 `SHA256SUMS.txt` 核对下载文件；安装时直接选择 ZIP，无需解压。
2. 在 IDEA 中打开 **Settings → Plugins → 齿轮菜单 → Install Plugin from Disk**，选择 ZIP，按提示完成安装。
3. 打开一个项目，运行 **Tools → 注释译读 → 打开离线体验示例**。示例包含行注释、行尾注释、单行/多行文档注释和长译文；使用固定译文，不调用模型，也不写入翻译缓存。
4. 运行 **Tools → 注释译读 → 配置翻译服务…**，填写自己的服务地址和模型。API Key 如有需要也在此设置。

菜单也可从源码编辑器右键菜单顶部进入，或通过 IDEA 的 Find Action 搜索动作名称。安装与体验不需要额外安装 Node.js。

## 语言与显示范围

| 文件 | 当前支持 |
| --- | --- |
| Java | `//`、`/* */`、单行与多行 Javadoc |
| Kotlin（`.kt`、`.kts`） | 行注释、块注释和 KDoc |
| XML/HTML（含 XSL、XHTML） | 宿主中的 `<!-- -->` 注释；排除属性和 CDATA 等非注释内容 |

注释由 IDE 的 PSI 和词法信息识别，连续相邻的独立行注释可合并翻译。译文恢复原注释的符号、缩进和外壳，校验文档标签、参数名及可识别的 XML/HTML 标记。

在 **Settings → Tools → 注释译读 → 源码显示方式** 中选择：

| 显示方式 | 行为 |
| --- | --- |
| 原位译文（默认） | 独立行、连续行和文档注释在原位置显示完整多行译文，随编辑器宽度排版。行尾及代码中的注释只替换精确的注释范围，前后代码保持可见；这类译文的换行会合为空格，通过复制译文或只读快照可获取完整多行内容。 |
| 上下对照 | 保留原注释，在下方显示无边框译文。默认预览四行，点击“展开”阅读全文，“收起”恢复预览；行尾注释的译文也显示在该行下方。 |

原位模式下，悬停译文查看原注释，点击译文可恢复原文进行编辑。所有光标和选区离开该注释后，已有译文自动恢复；任一光标仍在注释及其编辑边界内，或选区与注释重叠时，原文继续保持可编辑。修改原注释后，自动模式会重新扫描并取得对应译文，旧译文不会覆盖修改后的内容。需要提前切回译文时，可将光标放在该注释中，执行 **切换当前注释原文 / 展开译文**。此动作在上下对照模式中控制长译文的展开与收起。**复制当前译文** 单独复制完整译文，普通源码复制仍取原文。

切换显示方式、查看原文、展开和复制已有译文不请求模型，也不清空翻译缓存。原位模式会临时接管当前编辑器的内置 Rendered Documentation 显示；隐藏译文、切回上下对照或释放该显示后，恢复接管前的有效开启状态，不修改 IDE 全局设置。

本版尚未提供 Markdown 全文翻译、JS/TS/Vue 等语言适配，也不翻译 HTML 内嵌 JavaScript/CSS 的注释。通用注释校验保护文档标签与相关标记，不是对所有自然语言内的代码示例、普通 URL 的完整校验。

## 翻译、重试与只读快照

配置就绪且项目受信任时，默认自动翻译打开的受支持文本源码，无需先执行右键命令。本地文件、依赖 JAR 中的源码、只读源码和临时文本源码采用同样的流程：先扫描注释、按原文去重并查询 SQLite，已有译文直接显示，缺失的每条注释分别发送一个 HTTP 请求。连续相邻的独立行注释合并后视为一条；重复原文的结果可复用。每条请求完成并通过校验后立即缓存、显示，无需等待整个文件全部翻译完。仍须符合上表中的语言和文件类型范围；二进制 `.class` 文件不在此列。不会扫描整个项目。修改文件后撤下旧译文，自动模式会防抖重新扫描；旧请求结果不会覆盖新版本。

- **检查 / 继续翻译当前文件**：用于失败重试，或继续下一批未处理注释；成功缓存直接复用，只为缺失项请求模型。完成后提示处理结果；自动翻译正在进行时，此项显示“正在翻译当前文件…”并禁用，避免重复操作。
- **翻译当前注释**：只处理源码光标或右键所指的注释。
- **自动翻译**：控制自动请求；关闭时取消自动触发的任务，保留已完成的译文，仍可手动翻译。手动模式下修改注释后，需再次执行翻译动作。
- **隐藏当前文件译文 / 显示当前文件译文**：菜单根据当前显示状态提示下一步操作，只改变当前文件的显示，不关闭自动请求，也不删除缓存。
- **打开只读译文**：生成当前文件的只读译文快照，用已有译文替换快照中的对应注释，源文件不变。快照可以选中、复制；不会自动刷新，源文件变化后需重新打开。快照中的行数可能与源码不同。
- **清除本地翻译缓存**：取消已有任务、清空缓存和已有译文，保留自动翻译开关。自动翻译开启时，重新处理当前打开的受支持文件；关闭时，等待下一次手动翻译或重新开启自动翻译。

编辑器右键菜单按实际点击的文件、编辑器和注释定位，分屏时也使用该处上下文。当前文件尚无译文时，隐藏/显示与只读快照操作不可用；当前位置尚无译文时，复制与切换原文操作不可用。可从状态栏查看自动翻译进度，通常只需打开文件等待显示。

同一 IDE 的所有项目共用一个 HTTP 并发上限，可设 1–64，默认 10。后台仍最多由三个文件协调任务负责扫描、缓存和结果汇总，HTTP 请求单独调度。以默认值为例，只有一个文件待翻译时，它也可以同时发送最多 10 条注释请求；多个文件同时处理时，共享这 10 个名额，等待的文件轮流获得空闲名额。每个请求只包含一条注释，失败重试也按单条处理。

自动翻译先准入 500 个去重后的缺失项，缓存命中不占额度，达到上限后可手动继续。验证版单文件上限为 200 万字符。单条注释字符上限默认 16,000，沿用旧设置 `maxBatchChars` 中已保存的值；检查时包含该条注释的 JSON 数据开销。超长注释会提示提高上限，不会切碎或截断后发送。

## 模型配置与本地缓存

配置入口为 **Settings → Tools → 注释译读**。

| 设置 | 默认值 / 说明 |
| --- | --- |
| 服务地址 | 自定义 HTTP/HTTPS 地址，例如 `https://your-provider.example/v1`、`http://localhost:8000/v1`，也支持完整 `/chat/completions` 地址 |
| 模型 | 服务支持的任意模型 ID |
| API Key | 保存在 IDE 凭据库，按服务地址区分；留空保留该服务已有值，无认证服务可不配置 |
| 目标语言 | 简体中文 |
| 附加翻译要求 | 可填写术语和表达偏好 |
| 请求超时 | 60 秒，可设 5–300 秒 |
| 同时翻译的注释数 | 10，可设 1–64；这是整个 IDE 共享的 HTTP 并发上限 |
| 输出格式 | 默认 JSON Object（`json_object`），发送 `response_format: {"type":"json_object"}`；兼容文本（`text`）省略 `response_format` 参数 |
| 温度 | 0.2，可设 0–2；发送给支持该参数的模型 |
| 思考模式 | 默认“服务默认”（`provider`），不发送 `thinking` 参数，保留服务自身行为；可显式选择“关闭思考”（`disabled`）或“开启思考”（`enabled`） |
| 单条注释字符上限 | 16,000，可设 1,000–200,000；沿用旧 `maxBatchChars` 保存值，包含单条 JSON 数据的字符开销，不等同于模型 token 数 |
| 自动翻译 | 默认开启，服务配置完成后生效 |
| 源码显示方式 | 默认“原位译文”，也可选择“上下对照”；只切换显示时直接复用已有译文 |

模型先判断注释中的自然语言说明是否已经符合目标语言。若全部符合，只返回 `{"same":true}`，不输出原文或译文；本地恢复原文并将其存入已有 SQLite 缓存，下次直接命中。代码、标识符、URL 与文档标签不算需要翻译的说明；混合语言仍有非目标语言说明、简繁等目标变体不符或无法确定时，继续正常翻译。已经符合目标语言的注释保留原来的符号、空白和缩进，不增加折叠或重复译文。状态中的处理条数包含这些无需翻译的注释；没有实际译文变化时，复制/展开译文及文件译文显示、只读译文入口不会启用。含真实译文的只读快照仍精确保留那些无需翻译的原注释。

这个短标识是向后兼容的响应扩展，旧缓存继续复用，普通译文仍按原 `translations` 协议解析。`same` 必须是独立对象中的布尔值 `true`；字符串、空值以及与译文混在一起的矛盾响应不会写入缓存。首次判断仍需一次请求及输入 token，节省的是重复输出整段原文的输出 token；服务端思考成本仍由思考模式决定。

接口采用 OpenAI Chat Completions 兼容格式，固定非流式请求。默认通过 `response_format` 要求 JSON Object；服务不接受该参数时，可选择兼容文本模式将其省略。两种模式的提示词仍要求 JSON 内容，本地仍校验注释 ID 和结构，兼容文本模式不接受任意纯文本译文。当前没有 JSON Schema 模式、输出 token 上限或自定义认证头设置；仅提供 Responses 或厂商原生协议的接口需要兼容代理。服务地址不能包含账号、密码、查询参数或片段；请求不自动跟随重定向。

思考模式保持“服务默认”时，插件不替服务决定是否开启思考。显式开启或关闭会发送 `thinking: {"type":"enabled"}` 或 `thinking: {"type":"disabled"}`，需要服务支持该扩展参数。DeepSeek 思考模式下，温度参数即使传入也不会生效，详见 [DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。

重新打开设置不会显示已保存的 Key。要移除凭据，请勾选“删除此服务已保存的 Key”；删除后自动翻译也会关闭。服务与凭据设置保存期间暂停请求，凭据不写入项目 `.idea`、SQLite、日志或译文页面。

缓存位于 IDE 系统数据目录下的 `puhui-comment-translator/translations.sqlite`，由同一 IDE 的多个项目复用。保存注释原文、译文与非敏感配置标识，默认不按时间过期，最多保留 10,000 条，按使用顺序淘汰。缓存键沿用原文、语言、服务地址、模型、目标语言、Prompt 与协议版本；更换 Key 本身不使缓存失效。并发、输出格式、温度和思考模式不进入缓存键，调整这些参数不会使旧缓存全部失效，单条字符上限也不改变缓存身份。若要让已经缓存的译文按新参数重新生成，需要先执行 **清除本地翻译缓存**；仅点击“检查 / 继续翻译当前文件”仍会复用缓存。

IDEA 与 VS Code 使用各自独立的数据库，目前没有跨端缓存导入功能。注释仅在需要翻译时发送到配置的服务；插件不提供额外的中转服务器。

## 构建与验证

准备 JDK 25，并将 `JAVA_HOME` 指向其安装目录。使用仓库自带的 Gradle Wrapper，无需全局安装 Gradle：

```sh
cd idea-plugin
./gradlew test buildPlugin
```

默认从官方仓库解析 IDEA `2026.2.0.1` 及构建依赖。产物为 `build/distributions/idea-comment-translator-0.1.6.zip`；Windows 使用 `gradlew.bat`。

也可指定本机同版本 IDEA，减少下载：

```sh
./gradlew -PlocalIdePath="/path/to/idea" test buildPlugin
```

`localIdePath` 指向 IDE 安装根目录；macOS 为 `.app/Contents`。在隔离开发沙箱中启动插件：

```sh
./gradlew runIde
```

运行沙箱也可传 `-PlocalIdePath`；可选 `-PqaProject="/path/to/test-project"` 指定测试项目。单元测试、平台测试和接口验证使用 Mock 数据或本地 HTTP 服务，不需要模型 Key。测试报告在 `build/reports/tests/test/index.html`，JUnit XML 在 `build/test-results/test/`。

独立的 [IDEA 工作流](../.github/workflows/idea.yml) 在相关分支变更时测试和打包；与 `gradle.properties` 中 `pluginVersion` 一致的 `idea-v*` 标签会触发 GitHub 预发布，上传插件 ZIP 与 `SHA256SUMS.txt`。JUnit/HTML 报告作为 Actions 产物保留。该流程不发布到 JetBrains Marketplace。CI 在 Linux 上独立打包，产物的校验值可能与本地 ZIP 不同；下载发布包时，以同一 Release 附带的 `SHA256SUMS.txt` 为准。
